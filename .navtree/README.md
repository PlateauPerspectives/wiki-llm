# .navtree — NavTree Build Pipeline

Builds a NavTree v2 navigation structure from the Obsidian vault pages in
`../wiki/`. The output is a hierarchy of numbered folders with TOML metadata
and Markdown content, designed to be consumed by web apps like bibel-wiki
and navtree-app.

This folder is dot-prefixed so Obsidian ignores it in its file explorer,
search, and graph view.

## Quick start

```bash
cd .navtree
python3 build_navtree.py

# Output is written to .navtree/output/
ls output/
```

Requires Python 3.11+ (uses the standard-library `tomllib`). No other
dependencies.

## How the tree is built

1. **Roots** come from `../wiki/index.md`: the first `[[wikilink]]` on each
   top-level (non-indented) `- ` bullet under a `##` heading. A `---` line
   pauses this until the next `##` heading. Links matching `skip_prefixes`
   (`Sources/…`, `source-registry`) and names in `exclude_roots` (`log`)
   never become roots, which is why the Sources and Meta sections are ignored.
2. **Children** are found breadth-first by following `[[wikilinks]]` inside
   each page. Links starting with a `skip_prefixes` entry (e.g. `Sources/`)
   are not followed.
3. **Only `[[wikilinks]]` are followed.** Standard `[text](page.md)` links
   are invisible to the build.
4. **Frontmatter** fields of each page (except `title`) are copied into that
   node's `index.toml`; YAML lists become TOML arrays.

## What it produces

```
.navtree/output/
├── config.toml              # Global settings (media dirs, languages)
├── search-positions.json    # content_id → tree positions (for search)
├── redirects.toml           # Multi-position content (only if any exist)
├── 1/                       # Root node
│   ├── index.toml           # Metadata: content_id, title, frontmatter fields
│   ├── content.md           # Markdown content (syntax preserved as-is)
│   ├── 1/                   # Child node
│   │   ├── index.toml
│   │   └── content.md
│   └── 2/
│       ├── index.toml
│       └── content.md
└── 2/                       # Redirect node (content lives elsewhere)
    └── index.toml           # Contains: redirect_to = "1/3/2"
```

The folder hierarchy IS the navigation tree. No separate `tree.json` needed.
Apps walk the numbered folders and read `index.toml` at each level, the same
convention bibel-wiki uses.

## Deduplication via redirects

When the same note is linked from multiple places in the tree, it gets
content at its first occurrence and `redirect_to` at subsequent positions:

```toml
# output/2/index.toml — redirect, no content.md here
content_id = "creation-care"
title = "Creation Care / Stewardship"
redirect_to = "1/5/1"
```

The app follows the redirect to fetch content from the primary location.
`search-positions.json` tracks all positions so search results can link to any.

## AI agent integration

Two files coordinate between AI agents editing the vault and this build:

### `output/redirects.toml` — build tells agents what's multi-position

Generated by the build script, and only present when at least one note
appears at more than one tree position. Agents read this before making
structural changes.

### `vault-changelog.toml` — agents tell the build what changed

Written by AI agents in the **repository root** (parent of `.navtree/`)
whenever they rename, restructure, split or delete a multi-position note.
The build validates the entries (printing warnings), then appends them to
`vault-changelog.archive.toml` in the repo root and deletes the changelog.

The coordination rules are in `../CLAUDE.md` under "NavTree vault
coordination".

## Configuration

`build.toml` (paths are relative to `.navtree/`):

```toml
vault_path = "../wiki"                   # The wiki pages
output_dir = "output"                    # Output within .navtree/
skip_prefixes = ["Sources/", "source"]   # Link prefixes not followed
exclude_roots = ["log"]                  # Notes never used as roots
changelog_dir = ".."                     # Where vault-changelog.toml lives
```

## CI pipeline

`.github/workflows/navtree.yml` in this repository runs on every push to
`main` that touches `wiki/**/*.md` or `.navtree/**`:

```
push to main
   │
   ├─ cd .navtree && python build_navtree.py
   ├─ commit .navtree/output/ + vault-changelog.archive.toml
   │    as "[navtree] Rebuild navigation tree"
   │    (commits with "[navtree]" in the message don't retrigger the job)
   └─ if output changed: repository_dispatch "navtree-updated"
        → larsgson/stewardship-navTree  (needs secret NAVTREE_SYNC_TOKEN)
```

Because CI commits to `main` after your push, run `git pull --rebase`
before your next push.
